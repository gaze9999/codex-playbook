# Codex Playbook

這份指南說明如何用 Codex 完成開發工作, 從提出需求, 查閱專案, 修改程式到驗收成果, 也整理換電腦, 維護設定與研究新工具的方法

第一次使用時, 先完成一個小功能, 確認整個流程跑得通, 再加入分工或額外工具

## 依工作階段選擇入口

| 時機 | 做法與交付 |
| --- | --- |
| 開始或接手 | 依全域、工作區、專案規範找到目標與負責人, Codex 與 Claude 並行時各自確認分支、未提交差異與可寫範圍 [工作規範](governance.md) |
| 選方法或工具 | 需要重用判斷時讀 Skill, 要執行操作時選已有的 CLI 或 MCP, 需要一併安裝時才選 Plugin [工具選用](toolkit-roadmap.md) |
| 修改與測試 | 找到專案既有測試入口與預期結果, 在開發端驗證受影響行為, 分列實作與原生平台驗收 [開發流程](workflow.md) |
| 公開交付 | 核對來源版本、公開檔案及正式建置, 私人測試依專案政策保存, 回報哪些變更已驗證及哪些仍待部署 [公開內容檢查](docs/public-content.md) |
